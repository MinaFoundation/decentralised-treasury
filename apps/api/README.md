# API

This app wires the indexer and processor runtimes for treasury-owner events.

It exposes two HTTP surfaces:

- indexer events API (`start:api`)
- processor projection CRUD API (`start:processor`, generated by `@dataui/crud-typeorm`)

## Strict Event-Type Policy

Event type is treated as immutable at ingest:

- event types are derived from the contract class passed to `loadIndexerConfig(...)`
- indexer ingestion resolves type from archive-reported metadata or encoded event payload
- if type cannot be resolved, ingest throws (no `unknown` fallback)
- processor consumes only typed events (`includeUnknown=false`) and does not patch event types

## Run

From repo root:

```bash
pnpm --dir apps/api run check-types
pnpm --dir apps/api run migration:run
pnpm --dir apps/api run start:indexer
pnpm --dir apps/api run start:api
pnpm --dir apps/api run start:processor
```

Run `start:indexer`, `start:api`, and `start:processor` in separate terminals.

- `start:indexer` polls archive and stores typed events
- `start:api` serves events from the indexer table
- `start:processor` consumes events from indexer API, writes projections, and serves projection CRUD API

## APIs

### Indexer API (`start:api`)

- `GET /healthz`
- `GET /v1/indexer/events?updatedAfter=<iso>&eventIdAfter=<id>&eventTypes=<csv>&includeUnknown=true|false&limit=<n>`

Response shape:

- `items`: event rows
- `nextCursor`: `{ updatedAfter, eventIdAfter }` or `null`

Error strategy:

- `400`: query validation errors
- `500`: repository/internal server errors

### Processor CRUD API (`start:processor`)

Default prefix: `v1/processor`

- `GET /v1/processor/healthz`
- `GET /v1/processor/proposals`
- `GET /v1/processor/proposals/:id`

Routes are generated from projection entities via `@dataui/crud-typeorm` and are
read-only in the current app wiring.
